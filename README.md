# World Mapper

Flat Earth vs the Globe. Settling the debate once and for all.

Point a phone at the Sun or the Moon; the app measures how high it stands above level and when.
Enough readings from enough places decide the shape of the planet without assuming it in advance.

## What is in here

| Folder | What it is |
|---|---|
| `www/` | The app itself: `index.html` (splash, three steps, camera, saving) and `native.js` (the parts that only work in the installed app). This is also what the website serves. |
| `android/`, `ios/` | The native wrappers, generated by Capacitor. Rarely edited by hand. |
| `.github/workflows/` | `check.yml` on every push; `release.yml` on a version tag, which builds and uploads to both stores. |
| `fastlane/` | The upload lanes used by the release workflow. |
| `store/` | Listings, privacy policy and screenshots for both stores. |
| `tools/` | `check-page.js`, the guard that runs on every push. |
| `docs/` | The method, the simulation results, and the release runbook. |

## Day to day

Change `www/index.html`, then:

```bash
node tools/check-page.js     # does it still parse and hold together
npx cap sync                 # copy the page into both native projects
```

To release:

```bash
git tag v1.0.1 && git push origin v1.0.1
```

That builds the Android bundle and the iOS build and uploads them to Play internal testing and
TestFlight. Both arrive as drafts: nothing reaches anyone until you promote them in the consoles.
See `docs/release-runbook.md` for the accounts and keys this needs, which only you can create.

## What only works in the installed app

`www/native.js` is quiet on the website and comes alive in the app:

- **A real daily notification** at noon, from the phone itself. On the web it still offers a repeating calendar entry instead.
- **Checks that make a faked reading hard to pass off**: gravity should read 9.8 and never sit perfectly still, the phone's clock is compared against the server's, and an emulator, a jailbroken phone or switched-on fake locations are all recorded. Nothing is ever blocked; each reading carries an honesty score and the reasons, and the analysis decides what to do with them.
- **Phone-to-phone distance measuring** (`WmRanging`, written for both platforms). Each phone advertises its own short id over Bluetooth and listens for others; signal strength gives a distance, good to a few metres. Each pair becomes a row in the `Links` table.

That last one is the point of the whole exercise. Every reading records its position from GPS, which is worked out on the assumption of a round Earth — fine for checking that the app measures angles properly, useless for settling the question. Distances measured between phones assume nothing.

## The website version

The same `www/index.html` is uploaded to Wix (Edit Frontend → Upload Files) and served at the
project's web address. Keeping them one file means the web and the app never drift apart.
